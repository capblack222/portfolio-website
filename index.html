Lottery Verification Platform

Infrastructure and Networking Lead · 2026

A verification service where I owned the network and infrastructure layer, then kept extending it after the team build ended.

  • Designed AWS networking and container infrastructure across a multi-AZ VPC, ALB, ECS Fargate, and port-scoped security groups, with the full stack provisioned and torn down via 10 modular Terraform components.
  • Decoupled claim processing from the verification response path using SQS with a dead-letter queue (maxReceiveCount=3, 14-day retention), so verification stays available independently of claims-service failures.
  • Reduced p99 verification latency 20–50× — 80–150ms down to 2–10ms — with an ElastiCache Redis cache-aside layer, while excluding WINNER outcomes from caching to prevent stale claim state across agents.
  • Benchmarked with a purpose-built script and custom CloudWatch metrics (CacheHit, CacheMiss, VerificationLatency) before and after Redis, validating the cache across both cold and warm request paths.
  • Evaluated database-per-service decomposition and retained a shared RDS instance by design, with SQS payloads carrying enough context for the claims service to operate independently of the verification data tier.
